\# Security Policy



\## Reporting a vulnerability



The security of this project is taken seriously.



If you discover a security vulnerability, please do not disclose it publicly through GitHub Issues or other public channels.



Please report security concerns privately with:



\- a clear description of the issue;

\- steps to reproduce the vulnerability;

\- potential impact;

\- relevant technical details;

\- any suggested mitigation if available.



For confidential reporting, use GitHub's private vulnerability reporting feature when enabled for this repository.



\## Security principles



This project follows these security principles:



\- No secrets, credentials, or private keys are stored in this repository.

\- Validation logic is separated from private application infrastructure.

\- Official emergency data sources remain authoritative.

\- Missing provenance or incomplete records must not silently become trusted data.

\- Changes should preserve existing security controls.

\- Security issues should be handled responsibly and transparently.



\## Scope



This repository contains open-source validation tooling for emergency and public-safety data records.



The purpose of this project is to help developers detect incomplete or unsafe data structures before emergency-related information is consumed by applications.



This repository does not contain:



\- private user data;

\- production credentials;

\- emergency communication infrastructure;

\- push notification systems;

\- operational secrets;

\- private Portugal Safe application components.



\## Responsible disclosure



Researchers and developers who identify security issues are encouraged to report them responsibly.



Please allow reasonable time for investigation and remediation before public disclosure.



Thank you for helping improve the security and reliability of this project.
